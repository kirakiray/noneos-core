Peer interconnect

两个用户， 在一个页面里互相发消息

这个案例会创建两个独立身份、两个 SharedWorker Hub，通过本机 Rust Relay 完成认证、服务发现和消息投递。右侧聊天记录就是真实的 PeerSession 消息。

SharedWorker ECDSA 认证 PeerSession E2EE
演示步骤 1 / 4
    代码记录 保留每一步
    Step 01

    先启动本机 Relay

    NoneOS Core 不强制依赖中心服务器，但两个用户需要一条可达的信令/中继通道。 在项目根目录运行： 

    npm run relay

    默认监听 ws://localhost:8081。如果你改了端口，在下面填入对应地址。

    这个案例需要 Chrome / Edge 的模块化 SharedWorker 支持；Relay 没启动时，下一步会给出错误提示。
    重置本步
    Step 02

    创建两个身份并连接

    两个用户各自持有一对 ECDSA 密钥，各自启动一个 SharedWorker。 Hub 会先完成挑战应答认证，再建立 PeerSession。

    这一步成功后，右侧会出现两个 userId；它们是真正的公开身份。
    重新连接
    Step 03

    用服务发现找到对方

    两个用户都注册 noneos-case-chat 服务。 Hub 通过 Relay 查询这个 appId 下的在线用户，拿到对方的 userId。

    服务发现只返回公开的 userId；真正的消息仍然由 PeerSession 点对点/中继传输。

    重新查询
    Step 04

    开始聊天

    从 A 或 B 输入一句话并发送。消息经 E2EE 加密后由 PeerSession 可靠投递，另一端解密并显示。
