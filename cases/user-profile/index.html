Case 02 / 03
Identity & profile

创建一个用户， 然后慢慢完善资料

NoneOS Core 5.0 的身份是一对 ECDSA P-256 密钥，userId 由公钥哈希得到。用户名、简介这些资料属于应用数据，由应用自己保存和更新—— 这正是本案例要演示的分层。

ECDSA P-256 userId nos/storage 资料更新
演示步骤 1 / 4
    代码记录 保留每一步
    Step 01

    创建或加载本机用户

    loadOrCreateIdentity() 会从 nos/storage 读取已有身份；如果没有，就用 WebCrypto 生成一对 P-256 密钥并保存。

    私钥只留在本机存储中，userId 是由公钥计算出的公开标识，可以放心展示给对方。

    这一步是“用户系统”的地基：先有身份，才有后面的资料和互联。
    重新加载身份
    Step 02

    写入第一版资料

    身份只负责“你是谁”，资料负责“别人怎么认识你”。 这里把昵称和简介写入以 userId 为键的应用存储空间。

    重新填写 点击「下一步」保存这一版
    Step 03

    更新资料

    同一个 userId，同一把存储键。修改昵称和简介后再保存， 读取时就会得到更新后的版本和新的 updatedAt。

    重新填写 点击「下一步」保存更新
    Step 04

    读取并验证

    最后从存储里按 profile:<userId> 读取一次。右侧会显示完整的资料 JSON 和更新时间。

    这说明：身份是稳定的，资料是可迭代的。应用可以随时扩展字段， 而不会改变用户的 userId。
    重新读取 复制 userId
